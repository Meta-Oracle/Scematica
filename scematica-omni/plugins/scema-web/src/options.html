SCEMATICA OMNI — PAIRING

The extension talks to a scema-omnid running on this machine. Nothing is sent anywhere else, and the daemon binds to loopback only.

not tested

STARTING THE DAEMON

scema-omnid --allow /path/to/a/project
cat .scema/omnid.token

The token is generated once and reused, so pairing survives restarts. Delete the file to rotate it — every paired client will need the new one.

The token stays in this settings page and the extension's service worker. It is never given to the overlay running on a web page, so a hostile page that subverted the overlay still could not drive your agent.

WHAT THIS TALKS TO

Only 127.0.0.1. That is the extension's entire host permission, and it is the reason the daemon can refuse CORS outright and still be usable — a service-worker fetch under host_permissions is not subject to it, while a web page is.

It does not talk to the Scematica website, and does not need to. The page you are browsing is the extension's input; your own daemon is what processes it. Nothing is sent anywhere else.

The site's /omni page is a separate thing on the same project: an offline reader for records scema decide has already sealed. It shares no code path, no server and no network with this extension.
